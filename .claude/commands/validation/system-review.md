# 系统审查

对实施与计划的吻合程度进行元层面分析，并识别流程改进。

## 目的

**系统审查不是代码审查。** 你不是在寻找代码中的 bug —— 你是在寻找流程中的 bug。

**你的工作：**

- 分析计划遵循和偏离模式
- 识别哪些偏离是合理的，哪些是有问题的
- 找出防止未来问题的流程改进
- 建议更新第一层资产（CLAUDE.md、计划模板、命令）

**哲学：**

- 好的偏离揭示计划限制 → 改进规划
- 坏的偏离揭示需求不清晰 → 改进沟通
- 重复的问题揭示缺少自动化 → 创建命令

## 上下文和输入

你将分析四个关键工件：

**计划命令：**
阅读此文件以了解规划过程和指导计划创建的指令。
.claude/commands/plan-feature.md

**生成的计划：**
阅读此文件以了解代理应该做什么。
计划文件：$1

**执行命令：**
阅读此文件以了解执行过程和指导实施的指令。
.claude/commands/execute.md

**执行报告：**
阅读此文件以了解代理实际做了什么以及为什么。
执行报告：$2

## 分析工作流程

### 步骤 1：理解计划的方法

阅读生成的计划（$1）并提取：

- 计划了什么功能？
- 指定了什么架构？
- 定义了什么验证步骤？
- 参考了什么模式？

### 步骤 2：理解实际实施

阅读执行报告（$2）并提取：

- 实施了什么？
- 什么与计划发生了偏离？
- 遇到了什么挑战？
- 什么被跳过了以及为什么？

### 步骤 3：对每个偏离进行分类

对于执行报告中识别的每个偏离，分类为：

**好的偏离 ✅**（合理的）：

- 计划假设了代码库中不存在的东西
- 在实施期间发现了更好的模式
- 需要性能优化
- 发现安全问题需要不同的方法

**坏的偏离 ❌**（有问题的）：

- 忽略了计划中的明确约束
- 创建了新架构而不是遵循现有模式
- 采取了引入技术债务的捷径
- 误解了需求

### 步骤 4：追踪根本原因

对于每个有问题的偏离，识别根本原因：

- 计划哪里不清晰，为什么？
- 缺少上下文，在哪里，为什么？
- 缺少验证，在哪里，为什么？
- 手动步骤重复，在哪里，为什么？

### 步骤 5：生成流程改进

基于跨偏离的模式，建议：

- **CLAUDE.md 更新：** 要记录的全模式或反模式
- **计划命令更新：** 需要澄清或缺少步骤的指令
- **新命令：** 应该自动化的手动流程
- **验证添加：** 可以更早发现问题的检查

## 输出格式

将分析保存到：`.agents/system-reviews/[功能名称]-review.md`

### 报告结构：

#### 元信息

- 审查的计划：[$1 的路径]
- 执行报告：[$2 的路径]
- 日期：[当前日期]

#### 整体对齐分数：__/10

评分指南：

- 10：完全遵循，所有偏离都合理
- 7-9：轻微合理的偏离
- 4-6：合理和有问题的偏离混合
- 1-3：主要的有问题的偏离

#### 偏离分析

对于执行报告中的每个偏离：

```yaml
偏离： [什么改变了]
计划： [计划指定的内容]
实际： [实际实施的内容]
原因： [报告中代理陈述的原因]
分类： 好 ✅ | 坏 ❌
合理： 是/否
根本原因： [计划不清晰 | 缺少上下文 | 等等]
```

#### 模式合规

评估对记录模式的遵循：

- [ ] 遵循代码库架构
- [ ] 使用记录的模式（来自 CLAUDE.md）
- [ ] 正确应用测试模式
- [ ] 满足验证要求

#### 系统改进行动

基于分析，建议具体行动：

**更新 CLAUDE.md：**

- [ ] 记录实施期间发现的 [模式 X]
- [ ] 添加 [Y] 的反模式警告
- [ ] 澄清 [技术约束 Z]

**更新计划命令 ($1)：**

- [ ] 添加 [缺少步骤] 的指令
- [ ] 澄清 [模糊指令]
- [ ] 为 [X] 添加验证要求

**创建新命令：**

- [ ] `/[命令名称]` 用于 [手动流程重复 3+ 次]

**更新执行命令 ($3)：**

- [ ] 在执行清单中添加 [验证步骤]

#### 关键学习

**什么进展顺利：**

- [具体顺利的事情]

**什么需要改进：**

- [识别的具体流程差距]

**下次实施：**

- [尝试的具体改进]

## 重要

- **具体：** 不要说"计划不清晰" —— 说"计划没有指定使用哪种认证模式"
- **关注模式：** 一次性问题不可操作。寻找重复的问题。
- **面向行动：** 每个发现都应该有具体的资产更新建议
- **建议改进：** 不要只是分析 —— 实际上要建议添加到 CLAUDE.md 或命令中的文本
