# 规划新任务

## 功能：$ARGUMENTS

## 使命

通过系统的代码库分析、外部研究和战略规划，将功能请求转化为**全面的实施计划**。

**核心原则**：我们在此阶段不编写代码。我们的目标是创建一个上下文丰富的实施计划，使 AI 代理能够一次性成功实施。

**关键理念**：上下文为王。计划必须包含实施所需的所有信息 - 模式、必读文档、验证命令 - 以便执行代理能够一次成功。

## 规划流程

### 阶段 1：功能理解

**深度功能分析：**

- 提取要解决的核心问题
- 识别用户价值和业务影响
- 确定功能类型：新能力/增强/重构/Bug 修复
- 评估复杂度：低/中/高
- 映射受影响的系统和组件

**创建用户故事格式或细化（如果用户提供）：**

```
作为 <用户类型>
我想要 <行动/目标>
以便 <收益/价值>
```

### 阶段 2：代码库智能收集

**使用专业代理和并行分析：**

**1. 项目结构分析**

- 检测主要语言、框架和运行时版本
- 映射目录结构和架构模式
- 识别服务/组件边界和集成点
- 定位配置文件（pyproject.toml、package.json 等）
- 查找环境设置和构建流程

**2. 模式识别**（当有益时使用专业子代理）

- 在代码库中搜索类似的实现
- 识别编码约定：
  - 命名模式（CamelCase、snake_case、kebab-case）
  - 文件组织和模块结构
  - 错误处理方法
  - 日志模式和标准
- 提取功能领域的常见模式
- 记录要避免的反模式
- 检查 CLAUDE.md 中的项目特定规则和约定

**3. 依赖分析**

- 编制与功能相关的外部库
- 了解库的集成方式（检查导入、配置）
- 在 docs/、ai_docs/、.agents/reference 或 ai-wiki 中查找相关文档
- 记录库版本和兼容性要求

**4. 测试模式**

- 识别测试框架和结构（pytest、jest 等）
- 查找类似的测试示例作为参考
- 理解测试组织（单元 vs 集成）
- 记录覆盖率要求和测试标准

**5. 集成点**

- 识别需要更新的现有文件
- 确定需要创建的新文件及其位置
- 映射路由/API 注册模式
- 理解数据库/模型模式（如适用）
- 识别认证/授权模式（如相关）

**澄清歧义：**

- 如果此时需求不明确，在继续之前询问用户以澄清
- 获取特定的实施偏好（库、方法、模式）
- 在继续之前解决架构决策

### 阶段 3：外部研究与文档

**当有益时使用专业子代理进行外部研究：**

**文档收集：**

- 研究最新的库版本和最佳实践
- 查找带有特定部分锚点的官方文档
- 定位实现示例和教程
- 识别常见的陷阱和已知问题
- 检查破坏性更改和迁移指南

**技术趋势：**

- 研究技术栈的当前最佳实践
- 查找相关的博客文章、指南或案例研究
- 识别性能优化模式
- 记录安全考虑

**编译研究参考：**

```markdown
## 相关文档

- [库官方文档](https://example.com/docs#section)
  - 特定功能实现指南
  - 原因：X 功能需要
- [框架指南](https://example.com/guide#integration)
  - 集成模式部分
  - 原因：展示如何连接组件
```

### 阶段 4：深度战略思考

**更深入地思考：**

- 此功能如何适应现有架构？
- 关键依赖项和操作顺序是什么？
- 可能出现什么问题？（边界情况、竞态条件、错误）
- 如何全面测试？
- 有什么性能影响？
- 是否有安全考虑？
- 这种方法的可维护性如何？

**设计决策：**

- 有明确理由地选择替代方法
- 为可扩展性和未来修改而设计
- 如需要，为向后兼容性做计划
- 考虑可扩展性影响
